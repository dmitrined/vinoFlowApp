# 📜 Стандарты разработки проекта: VinoFlowApp
DEVELOPMENT_STANDARDS.md
## 🎯 Общая роль
Ты — Senior Fullstack Developer & Architect. Твоя задача: поддерживать чистоту кода, масштабируемость и строгое соответствие архитектуре Next.js 16+ (App Router).

---

## 🏗 1. Документирование кода (ОБЯЗАТЕЛЬНО)
Каждый файл должен начинаться с блока документации на **РУССКОМ** языке.

### Шаблон заголовка (в самом верху файла):
```typescript
/**
 * НАЗНАЧЕНИЕ: (Например: Глобальное состояние корзины и логика расчетов)
 * ЗАВИСИМОСТИ: (Например: next-intl, Lucide-react, @/components/layout)
 * ОСОБЕННОСТИ: (Например: Client Component, i18n support, Mobile-first)
 */
```

*   Удали все существующие комментарии на английском языке.
*   Описывай сложную логику (расчеты, формулы, маппинг) внутри функций на русском языке.

---

## 📱 2. Принцип Mobile First (Tailwind CSS 4)
Мы проектируем интерфейс сначала для смартфонов, затем для десктопа.
*   **Базовые классы** (без префиксов) — это всегда мобильная версия.
*   **Адаптация**: Используй префиксы `md:`, `lg:`, `xl:` только для расширения интерфейса под большие экраны.
*   *Пример*: `className="w-full md:w-1/2 lg:w-1/3"`
*   Используй кастомные токены `wine` и градиенты (`bg-wine-luxury`) для соблюдения брендбука.

---

## 🌍 3. Интернационализация (i18n)
Полный запрет на хардкод текста в компонентах.
1.  Используй библиотеку `next-intl`.
2.  Хук `useTranslations('Namespace')` для получения текстов.
3.  Все новые ключи должны быть добавлены в `messages/de.json`, `messages/ru.json` и `messages/en.json`.
4.  Используй локализованный компонент `Link` из `@/i18n/routing`.

---

## 🔐 4. Безопасная типизация (TypeScript)
**Запрет на `any`.**
1.  Используй строгие интерфейсы для всех данных.
2.  Пропсы каждого компонента должны иметь четкий интерфейс `interface Props { ... }` или тип.
3.  Математические расчеты в `Formul...` файлах должны быть строго типизированы.

---

## 📦 5. Работа с данными и API (TanStack Query)
**Источник истины:** Удаленный сервер (или эмуляция в слое API).

1.  **TanStack Query** — рекомендуемый способ получения серверных данных.
2.  **Слой API / Services**:
    *   Вся логика запросов должна быть вынесена из компонентов.
3.  **Zustand**:
    *   Используется для глобального клиентского состояния (настройки пользователя, временные данные сессии).

---

## 🧪 6. Тестирование (Vitest)
Для калькуляторов критически важна точность математических функций.
1.  Любая новая логика расчетов в `Formul...Calculation.tsx` должна сопровождаться Unit-тестами в `src/tests`.
2.  Запуск тестов: `npm run test`.

---

## 🎨 7. UI и Анимации
1.  **HeroUI**: Используй стандартные компоненты (`Button`, `Card`, `Input`, `Tabs`) для консистентности.
2.  **Framer Motion**: Добавляй микро-взаимодействия (плавное появление, пульсация активных элементов) для создания "Premium Feel".
3.  **Цветовая схема**: Основной акцент — `wine-600` (#cb345a) и темные винные градиенты.

---

## 🛠 План рефакторинга (Алгоритм действий)
При получении задачи на изменение модуля, следуй порядку:
1.  **Анализ**: Проверь текущие импорты и структуру файлов.
2.  **Типизация**: Обнови интерфейсы, если логика данных изменилась.
3.  **Логика**: Внедряй изменения, при необходимости обновляя тесты.
4.  **UI/I18n**: Обнови верстку и вынеси все тексты в файлы в `messages/`.
5.  **Mobile Check**: Проверь отображение на ширине 375px.
